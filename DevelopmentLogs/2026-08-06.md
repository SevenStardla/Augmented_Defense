# 2026-08-06 작업 기록

## 작업 목표

증강 흐름을 코드에서 따라가며 파일, 클래스, GameObject, 컴포넌트와 이벤트의 관계를 이해한다.

## 코드 흐름 확인

다음 순서로 증강 흐름을 확인했다.

```text
Start Wave 버튼
→ WaveManager.StartNextWave()
→ WaveManager.RunWave()
→ GameManager.EnterAugmentPhase()
→ GameManager.SetState(AugmentPhase)
→ StateChanged 이벤트
→ AugmentSelectionUI.HandleStateChanged()
→ AugmentManager.RollOffers()
→ 증강 선택
→ AugmentManager.SelectAugment()
→ ApplyAugment()
→ RuntimeAugmentStats 변경
→ BuildPhase 복귀
```

## 리팩터링

- `UIManager.cs` 안에 함께 있던 `AugmentSelectionUI` 클래스를 `AugmentSelectionUI.cs`로 분리했다.
- `AugmentManager.cs` 안에 함께 있던 `RuntimeAugmentStats` 클래스를 `RuntimeAugmentStats.cs`로 분리했다.
- 클래스 이름과 파일 이름을 일치시켜 검색과 Unity Inspector 확인이 쉬워졌다.
- 프로젝트 전체 검색으로 각 클래스가 한 번만 정의된 것을 확인했다.
- `git diff --check`에서 코드 공백 오류는 발견되지 않았다.

## PlayMode에서 직접 확인한 내용

- Hierarchy에 `Augment Selection UI` GameObject가 생성되는 것을 확인했다.
- 해당 GameObject를 선택했을 때 Inspector에 `Augment Selection UI (Script)` 컴포넌트가 붙어 있는 것을 확인했다.
- 웨이브 종료 후 Hierarchy에서 `Augment Selection Panel`이 활성화되는 것을 확인했다.

위 확인을 통해 다음 흐름이 실제로 동작한다는 것을 검증했다.

```text
웨이브 종료
→ AugmentPhase 상태 변경
→ StateChanged 이벤트 발생
→ AugmentSelectionUI가 이벤트 수신
→ Augment Selection Panel 활성화
```

## 배운 점

- Hierarchy에는 GameObject가 표시되고 Inspector에는 선택한 GameObject의 컴포넌트가 표시된다.
- `.cs` 파일은 코드를 담는 파일이고 `MonoBehaviour` 클래스는 GameObject에 붙어 실행되는 컴포넌트가 될 수 있다.
- 이벤트를 사용하는 코드는 직접 함수 호출이 보이지 않아도, 미리 구독한 함수가 이벤트 발생 시 실행된다.
- 기능을 새로 추가하지 않아도 코드 구조를 정리하고 실제 동작을 검증하는 것은 개발 작업이다.
