# 2026-08-05 작업 기록

## 작업 목표

OpenAI Game Builders Seoul의 2026년 8월 26일 제출을 기준으로 프로젝트 전체 상태를 점검하고, 제출을 막는 핵심 게임 흐름을 먼저 복구한다.

## 프로젝트 점검

- Unity 버전이 `6000.0.78f1`인 것을 확인했다.
- 빌드 설정에 `Assets/Scenes/Main.unity`가 포함된 것을 확인했다.
- 기본 웨이브 전투, 타워 배치, 플레이어 공격, 골드, 코어 체력, 승패 상태가 구현되어 있었다.
- `AugmentManager.ApplyAugment()`가 로그만 출력하고 실제 효과를 적용하지 않는 상태였다.
- 웨이브가 끝나면 `AugmentPhase`에 진입하지만 증강을 선택할 UI와 다음 웨이브로 돌아가는 정상 경로가 없었다.
- 씬의 Camera와 `DemoBootstrap`이 생성하는 Camera가 중복될 가능성을 발견했다.
- WebGL 빌드와 공개 링크는 아직 검증되지 않았다.

## 구현한 내용

- 씬에 Camera가 있으면 `DemoBootstrap`이 해당 Camera를 재사용하도록 변경했다.
- 웨이브 종료 후 증강 후보 3개를 보여주는 선택 UI를 추가했다.
- 증강을 선택하기 전에는 다음 웨이브 버튼을 사용할 수 없도록 했다.
- 증강 선택 단계에서는 타워를 배치할 수 없도록 했다.
- 다음 실제 증강 효과를 연결했다.
  - 타워 피해 증가
  - 타워 공격속도 증가
  - 타워 사거리 증가
  - 디펜더 피해 증가
  - 적 처치 골드 증가
  - 코어 체력 회복
- 마지막 웨이브 이후 승리 패널과 `Play Again` 버튼을 추가했다.
- 제출일까지의 실행 계획과 역할 분담을 `SUBMISSION_EXECUTION_PLAN.md`에 작성했다.

## 검증 결과

- `Assembly-CSharp.csproj` 빌드 결과: 경고 0개, 오류 0개.
- `git diff --check`에서 코드 공백 오류는 발견되지 않았다.
- Unity PlayMode 전체 완주 검증은 다음 작업으로 남겼다.

## 배운 점

- 게임의 이름과 핵심 콘셉트가 증강이라면 증강은 단순한 UI가 아니라 실제 능력치 변화까지 연결되어야 한다.
- `GameState`를 사용하면 Build, Wave, Augment, GameOver, Clear 단계의 입력과 UI를 한 기준으로 제어할 수 있다.
- 제출 프로젝트는 신규 기능 수보다 시작부터 승리·패배·재시작까지 끊기지 않는 흐름이 먼저다.

## 다음 확인 항목

- Unity에서 첫 웨이브 종료 후 증강 카드가 나타나는지 확인한다.
- 증강 선택 전후로 Start Wave 버튼 상태가 바뀌는지 확인한다.
- 증강 효과가 기존 타워와 플레이어에게 실제 적용되는지 확인한다.
- 승리와 게임오버 후 재시작을 확인한다.
